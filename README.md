## v4.21 · 个人借贷 P2P（群友之间互相借钱）

### 为什么做

银行借款是“定制化的信用资金”，它有利率、有额度、有过关手续费，但它不是“人情”。
群友之间真正有需求的是另一种：**有人先拿出钱来，利率当面谈，到期人还不上** ——
而这种事没有任何机构能给你保障，只能靠机制设计出“借款人跑不掉”。

核心一句话：**借出人承担真实风险，系统垫一半，借款人跑不掉。**

### 三档状态

| 状态 | 触发 | 后果 |
|---|---|---|
| 正常 | 按时还款 | 信用分 +3（提前还清再 +1） |
| 逾期 | 超过到期日 | 罚息 = 日息 ×3（全部归债主），信用分 −10 |
| 破产 | 值负赞了 | 系统垫 50% 给债主，剩 50% 进失信期 |

**失信期**：打工 / 签到收入的 30% 强制拿去还债；不能再申请 P2P；进公开失信榜。

### 设计口径（改代码前先看这里）

- **利率单位是千分之（℃）**：`0.5` = 万分之五 = 日息 0.05%；`0` = 免息互助。不是百分之。
- **债主自己破产** → 该笔债对借款人**打 5 折**（风险对称）。
- **司法重整**（破产清盘）**只免银行债**，P2P 债不参与；且 P2P 未清时保持 `bankrupt=1`（防重复垫付白快）。
- **P2P 债计入 `users.loan`** → 自动继承强平 / 破产 / 计息风控。
- **利息不进任何收入统计**（ledger reason 用 `P2P收款%` / `P2P还款` 等，不碰 `打工%` / `撒钱派发%`）。

### 堵漏清单

- 同一债主只能有一条待处理申请（否则“同意借款 小红”不知道回答哪一条）
- 同一对每天只能成交一笔（防对倖刷利息）
- 单笔 ≤ 20 万；出借人单笔 ≤ 现金 50%；待处理 ≤ 3 条
- 0 息免息也照样占债务额度（不能用免息绕过风控）

### 群指令

```
申请借款 5000 @小明 7     -> POST /api/g/p2p_apply
同意借款 小红 0.5          -> POST /api/g/p2p_decide   accept=true
拒绝借款 小红              -> POST /api/g/p2p_decide   accept=false
我的借贷                       -> GET  /api/g/p2p_info
还P2P 5000                              -> POST /api/g/p2p_repay
失信榜                              -> GET  /api/g/p2p_defaults
```

`@某人` 兼容三种形态：`[CQ:at,qq=123]` / `[CQ:at,id=123]` / `[CQ:at,qq=-1,text=@昵称]` / 裸 `@昵称`。

### 网页端

- `GET /api/p2p` → 借贷面板（信用分 / 我借入 / 我借出 / 待处理 / 失信榜）
- `POST /api/p2p/apply` / `POST /api/p2p/decide` / `POST /api/p2p/repay`（令牌鉴权）
- 新增一个 tab：「借贷」，mobile 上不用切回群窗口发指令

## v4.19 · 手续费不再按成交额收（高杠杆不再被手续费吃掉本金）

### 问题

手续费按「成交额」收，而杠杆放大的正好是成交额 —— 手续费被同步放大：

| 杠杆 | 成交额 / 保证金 | 手续费（0.1%）占保证金 |
|---|---|---|
| 1 倍 | 1× | 0.10% |
| 5 倍 | 5× | 0.50% |
| 20 倍 | 20× | 2.00% |

20 倍下一来回，手续费就是本金的 2% —— 看起来「做对了」，实际上已经在亏。

现网实测（主群 11-17~11-20，剔掉 whale）：**16~20 倍玩家手续费占保证金 4.58%**，
而玩家手续费里**开仓费占 47.4%**。

### 改法一：手续费按杠杆封顶（`fee_leverage_cap`）

```
手续费基数 = 成交额 × min(1, cap / 杠杆)      # cap = 5
```

- 杠杆 ≤ 5 倍：**完全不受影响**（1 倍仓手续费占保证金仍是 0.21%）；
- 杠杆 > 5 倍：手续费只按 5 倍的成交额算，16~20 倍玩家的总负担从 **4.58% 降到 1.15%**；
- **开仓 / 平仓 / 强制平仓同一口径** —— 只封平仓费只能解决一半：
  16~20 倍玩家总负担只从 4.58% 降到 2.78%，两端都封才是 1.15%；
- 档位折扣（v4.7）和冷却税倍率照旧乘在封顶后的基数上；
- 关键实现：`market.py` 的 `fee_leverage_cap(cfg)` / `turnover_mult(cfg, n_today)`。

配置：`fee_leverage_cap`（默认 5；兼容旧名 `close_fee_leverage_cap`，0 = 不封顶，回到 v4.18 口径）。

### 改法二：换手阶梯税（`close_fee_turnover_free` / `close_fee_turnover_step`）

封顶把「高频短线的唯一一道闸」拆了，所以补一道按**频率**收的税：

```
倍率 = 1 + max(0, 今日已平仓笔数 - free) / step      # free = 20, step = 10
```

- 只统计**玩家自己**的平仓（`kind='close'`），**强平不计入**（被强平不是玩家选的，不该再罚一次）；
- 阶梯是**连续递增**而不是分档 —— 分档留了个洞（脚本每天做 19 笔就永远待在最便宜那档），连续递增没有这个洞；
- 现实依据：程序化交易报告制度 + 高频差异化收费（交易所 / 券商对频繁申报额外收费）；
  券商柜台 API 委托频率上限（个人 API 常见 1~3 笔/秒，超频会被限流或加价）；
  异常交易监控（短时间内大量反复申报会被重点关注）。

### 已知残余风险（下一版要收口）

**「耐心套利者」在 1 天沙盒里仍然是正 EV**：+7.33% / +3.62% / +12.58%（每笔折保证金）。
旧口径下就已经为正，cap5 把它放大约 5 倍。

- **根因不在费率，在市场模型**：「锚点回归 alpha」太大 —— 沙盒里完美的机械执行者每笔毛赚 7.46%，
  而真实玩家只有 4.4%/笔；
- **费率区分不了他们**：玩家里 49% 的平仓持仓 < 120 秒、46% 用 16~20 倍杠杆，
  画像和套利者高度重合；
- 费率唯一能区分的是**频率** —— 所以换手阶梯税是当前唯一有效的闸。

下一版的开关（两条路）：

1. **纯配置**：调 `close_fee_turnover_free` / `close_fee_turnover_step`（把 free 压到 10、step 压到 5，或直接关掉）；
2. **从市场模型侧收口 alpha**（更根治，但会影响所有玩家的收益曲线，要重新标定 M1/M2）。

**在收口之前，这条洞是已知的、记录在案的**，不是新 bug。

## v4.13 · 财阀基金（富豪的钱往哪儿去）

### 为什么做这个

现网实测（2026-11-20 09:00）：8 个群 / 611 人。主群 216 人，
总净值 534.6 亿，**中位数只有 9.9 万，top10% 占 100.00%**。
头名 Kaito 一天之内 100.45 亿 → 534.57 亿（20 倍杠杆日内做空，
吃到了 11-19 那次大盘级爆炸新闻砸出来的 -6.74%）。

差距真正被放大的不是「收益率」，而是**放大器**：
`max_margin_ratio = 3.0` 配上 20~30 倍杠杆，总名义仓位能开到净值的 60~90 倍，
1% 的日内波动 = 净值 ±15%。而按比例收的税对这种量级是零头
（534 亿 × 0.26% = 1390 万，他一天赚 434 亿）。

所以 v4.13 走两条腿：

### ① 收敛放大器

| 机制 | 参数 | 作用 |
|---|---|---|
| 大户名义仓位上限 | `whale_notional_ratio` = 20（净值 ≥ `whale_notional_min_equity` 5000 万才生效） | 名义仓位 ≤ **自有净资产** × 20 倍。20 倍杠杆下等价于「保证金不超过自己的现金」 |
| 会员费封顶跟净值走 | `tycoon_fee_cap_ratio` = 0.26% | 封顶 = `max(3 万, 净值 × 0.26%)`。原来封顶是绝对 3 万，巨富等于免税 |
| 持仓税 | `margin_tax_ratio` = 0.1%（净值 ≥ `margin_tax_min_equity` 500 万且有持仓） | 按保证金收，进全民分红池。持股越多缴越多，**不持股就收不到** |

> 大户仓位上限的基准是**自有净资产 = 净值 − 保证金**，不是净值。
> 净值里含保证金，而保证金 = 名义/杠杆，拿净值当基准这条永远不会触发。

### ② 给富豪一个「带风险的钱出口」

钱不是被收走，是被**押进一个可能血本无归的池子**。

```
出资：净值 ≥ fund_min_equity（1500 万）的玩家
      每天自动投 min(净值 × fund_ratio(5%), fund_max(200 万))
押注：基金按 fund_leverage(3 倍) 押「群内公司等权收益中位数 r」
      当日缴当日清（本金不留存，池子不会无限膨胀）
结算：基金净盈亏 = 出资 × (r × 杠杆 − 管理费 fund_fee(5%))
      盈利 → 押对的群友（fund_bet_cut 30%）+ 全民分红池（fund_pool_ratio 50%）+ 返给出资人
      亏损 → 出资人 100% 自扛（从现金扣到 0 为止）
群友：可以「押基金」押明天涨还是跌，fund_bet_max 1000 元/次、每天 1 次
      押对拿回本金 + 分盈利；押错本金直接进全民分红池
```

**群友侧设绝对上限**（`fund_pool_cap` 10 万 / `fund_bet_cap` 3 万）：
鲸鱼的体量是中位数的 500 万倍，按比例抽穷人一夜暴富，不按比例抽富豪那点钱又不够看。
所以富豪那边按比例（公平），群友那边设上限（经济不崩）。

管理费全额进全民分红池 —— 这就是「富豪去消费」的那笔钱，**而且是按比例的**。

### 幂等与补结算

`whale_fund_day`（跑过结算的日期）+ `whale_fund_last_day`（已结算到的市场日）
两个 meta 键保证：服务停机后重启，最多能**补结算 15 天**，不会重复发钱也不会漏发。

## 关键不变量（改代码前先看）

- **开盘不跳空**。跳空会把价格中心顶到涨跌停带的上半区，涨的行情被削、跌的不被削，
  系统性「少涨」。当日漂移改成**收盘前随机 300 秒窗口内摊推**（`drift_push_seconds`）。
- **涨跌停带以昨收为中心**。所以跨日那一行会把 `price` 和 `prev_close` 刷成同值，
  跨日瞬间必须先做 `daily_px` 快照，否则「今日复盘」涨跌恒为 0（v4.5 修的就是这个）。
- **价格 4 位小数**。每个 tick 的漂移量级必须 > 5e-5，否则被取整吃掉。
- **`market_daily_drift` 是「炒股长期跑赢打工」的旋钮**：
  打工无风险 +0.15%/天（普通股民日上限 150 元 / 10 万本金），市场目标 +1.8%/天。
  改它之后**当天生效**（`market_gap_target` 指纹字段，v4.5 加的）。
- **链接等同账户凭证**。只私信本人，群里只给一次性口令，兜底文案里绝不能出现链接。
- **改前端必须换 `index.html` 里的 `?v=`**。它是前端的单一事实来源：
  服务端 `/api/state` 回的 `static_ver` 就是从 `index.html` 里解析出来的 `?v=`，
  页面拿自己加载时的版本号一比就知道自己落后了，于是自动重载。
  忘了换 `?v=` = 群友永远看不到新 UI（且没有任何报错）。
- **`users.bankrupt_since` 只在进入破产时写一次**，退出破产时清零。
  `bankrupt_ts` 会被「净值回正 → 又跌回负数」的震荡刷新，导致强制清盘倒计时永远从头开始。
  改这块前务必看 `recovery.on_bankrupt` / `sync_bankrupt`。

## 编码提醒（血的教训）
